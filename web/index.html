OnboardIQ

It reads the manual. The device checks its answers.

Give Muse Spark a device's MIB files and it picks the objects to monitor for CPU, memory, temperature and fan. Every pick is then tested on the live device, and a wrong one goes back to the model with the evidence. This page replays recorded sessions of real devices.

How it works

  1. Identify

    Reads the device's own description to find which MIB files apply.

    Command line only

  2. Read

    Muse Spark reads the MIB text and picks one object per metric.

    Shown in the sessions

  3. Test

    The agent reads the object on the device, applies a real load and checks that it moves.

    Shown in the sessions

  4. Correct

    A pick that fails goes back to the model with the evidence for another try.

    Shown in the sessions

  5. Score

    Proven picks are polled and turned into a health score with a plain-English explanation.

    Shown in the health session

Run it live

The real agent runs now. Muse Spark reads the MIB text of a Linux host's net-snmp agent, every pick is tested on that device (inside this container, read-only), and CPU and memory are proven with a real load test. It takes about 3 minutes and uses real model calls, so it is limited: one run at a time, a pause between runs and a daily cap. Nothing you type is sent to the device.
