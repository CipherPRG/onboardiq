Ask the device what it is.

One read-only SNMP query. The answer names the system and its agent, which decides which MIB files apply.

Read its manual.

The MIB files describe every object the device can report. OnboardIQ reduces them to the lines that matter and hands them to Muse Spark.

The model picks one object per metric.

It quotes the MIB line it relied on and predicts how the value should move under load. A prediction can be tested.

The device tests the pick.

Baseline first, then real CPU load. This counter was meant to rise. It fell, so the pick is rejected.

Wrong pick, back to the model.

The model re-reads the manual with the measured evidence and picks again. The new pick rises under load: proven.

Only proven picks are scored.

Polled every 10 seconds into a health score with a plain-English explanation. Under a stress test it fell to 40, then recovered.

Run it live

This is the real agent, running now. Muse Spark reads the MIB files of a Linux host's net-snmp agent. Every pick is tested on that device, which runs read-only inside this container, and CPU and memory are proven with a real load test. A run takes about 3 minutes and uses real model calls, so runs are limited: one at a time, a pause between runs and a daily cap. Nothing you type is sent to the device.
